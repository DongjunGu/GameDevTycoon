# 런(회차) 밸런싱 시뮬레이터 설계 — v2

> 사무실비 난이도, 운과 실력의 비중, 이벤트·아이템·강화·아웃게임 밸런스를 **실제 게임과 같은 규칙으로 수천 판을 자동으로 돌려서** 검증하는 시뮬레이터입니다.
> 코드: `balance_sim.py`(본체), `sim_events.py`(이벤트 데이터). 파이썬 표준 라이브러리만 씁니다.
> 게임 프로젝트(`Assets/`)는 읽기만 하고 절대 수정하지 않습니다.
> 모든 분석은 **사무실 단계별로** 따로 냅니다. 사무실비·매출 배율·아웃게임 레벨디자인이 단계마다 다르기 때문입니다.

## 1. 명령과 하는 일

| 명령 | 하는 일 |
|---|---|
| `trace --stage N [--events]` | 직원 만족도를 주 단위로 출력. 월간 하락, 완성 회복, 이벤트, 조건 이벤트 표시 |
| `validate [--spec code]` | 가이드의 가정과 시뮬레이터 측정값을 단계별로 비교 |
| `enhroi` | **강화 손익**: +1강의 연간 매출 증가 vs 연봉 증가, 단계·성수별 + 권장 연봉 곡선 |
| `satvalue` | **단계별 만족도 가치**: 측정 분포 기반 + A/B 직접 측정 |
| `outgame` | **아웃게임 요소별 효과**: 카드·CEO 레벨·특성 하나씩, 단계별 |
| `items` | 아이템 실측 효용 + 구매 전략 6가지 비교 |
| `reach` | 스펙 × 유저 수준별 단계 도달률·파산 원인·플레이 시간 |
| `luck` / `inject` / `calibrate` | 운·실력 분해 / 효과 하나의 V 실측 / 사무실비 상승률 보정 |

`--spec guide`(기본)는 이벤트 가이드 설계안, `--spec code`는 지금 게임 코드의 이벤트입니다.

## 2. 강화 손익 — 연봉 때문에 손해인 구간 (`enhroi`)

### 2-1. 방법
- 단계별 대표 팀(가이드 §3-1)에서 직원 한 명의 성수만 바꿔 가며 계산했습니다.
  - +1강했을 때의 **작품당 기대 매출 증가 × 연간 작품 수**(1단계 3개, 2단계 2개, 3·4단계 1.5개)를 구합니다.
  - 기대 매출은 틱 기대값 + 팀장 점수 몬테카를로 + 창의성 + 매출 공식으로 계산합니다.
- 이것을 **연봉 증가(매년 영구)**와 비교합니다. 스펙 P0, 만족도 80 기준입니다.
- '팀장'은 그 파트 팀장인 직원, '일반'은 같은 직군의 팀장 아닌 직원입니다.

### 2-2. 결과 — 손해 구간이 있습니다
| 단계 | 일반 직원 기준 손해 시작 | 팀장 기준 손해 시작 | 대표 수치 (연간) |
|---|---|---|---|
| 1단계 | – (일반 직원 없음) | **10→11성** | 연봉 +1,500 vs 매출 +1,159 |
| 2단계 | **14→15성** | 16→17성 | 15성: 연봉 +10,000 vs 매출 +7,198 |
| 3단계 | **19→20성** | 19→20성 | 20성: 연봉 **+100,000** vs 매출 +41,211 |
| 4단계 | **19→20성** | 20→21성 (21성+는 팀장만 이득) | 22성: 연봉 +160,000 vs 매출 +124,647 |

- 강화비 회수 기간도 급격히 길어집니다. 2단계 13→14성은 16년, 3단계 17→18성은 8.6년입니다.
- **팀장 점수가 오히려 떨어지는 성수가 있습니다.** 10→11성, 20→21성에서 팀장 매출 증가가 거의 없거나 마이너스입니다.
  - 원인은 90/95/99 보너스 계수가 성수 구간(0~10 / 11~20 / 21~25)마다 **작아지게** 설정돼 있어서입니다(`LeaderBonusF`).
  - 같은 시점에 스트레스 가중치 M도 10성·19성에서 커져 burst 위험이 올라갑니다.
- 숙련 유저 정책을 "손해 구간에서는 강화 안 함"으로 바꾸자, P0 스펙의 4단계 도달률이 **0% → 68%**로 뛰었습니다.
  - 다시 말해 지금 구조에서는 **"강화를 참는 것"이 가장 큰 실력**입니다. 말씀하신 대로 기획 의도와 반대입니다.

### 2-3. 고치는 방향
목표는 "강화비 때문에 손해를 볼 수는 있어도, **연봉 상승분은 금방 메워져 이득**이라는 느낌"입니다. 이를 수치로 바꾸면 **연봉 증가 ≤ 그 성수가 주로 쓰이는 단계에서 늘어나는 연간 매출의 50%**가 됩니다. 나머지 50%가 순이득이 되어 강화비를 갚습니다.

| 도달 성수 | 주 단계 | 현재 연봉 증가 | 연간 매출 증가 (일반) | **권장 상한 (50%)** |
|---|---|---|---|---|
| 1~12성 | 1~2 | 100~3,000 | 397~6,056 | 현행 유지 가능 ✅ |
| 13성 | 2 | 4,500 | 6,214 | 3,100 |
| 14성 | 2 | 6,300 | 7,005 | 3,500 |
| 15성 | 2 | 10,000 | 7,198 | 3,600 |
| 16~19성 | 3 | 13,000~35,000 | 20,525~40,515 | 10,000~20,000 |
| **20성** | 3 | **100,000** | 41,211 | **20,600** |
| 21~25성 | 4 | 130,000~300,000 | 96,099~234,693 | 48,000~117,000 |

수치를 바꾸는 방법은 네 가지가 있고, 섞어서 써도 됩니다.
1. **연봉 증가를 위 상한 이하로 낮추기**: 가장 직접적입니다. 특히 14→15성(+10,000), 19→20성(+100,000)의 절벽을 완만하게 바꿉니다.
2. **고성수 스탯 증가량 올리기**: 연봉은 두고 14성 이상, 19성 이상의 주스탯 증가를 2~3배로 올립니다. 매출 증가 쪽을 키우는 방식이라 고성수의 "특별한 느낌"이 살아납니다.
3. **팀장 보너스 계수가 떨어지는 구간 없애기**: 11성·21성에서 90/95/99 보너스 계수가 낮아지지 않게 하거나, 그만큼 스탯으로 보상합니다.
4. **연봉을 매출에 연동하기**: 연봉 증가를 "그 직원이 만드는 매출의 x%"처럼 정의하면, 단계와 무관하게 항상 이득 구조가 유지됩니다.

> ⚠ 이 수치는 현재 모델 기준입니다. 버그 감점, 인기도·피로도, 테크트리가 아직 빠져 있습니다(§7). 실제 게임에서 매출 증가가 더 작으면 손해 구간은 더 넓어집니다.

## 3. 이벤트 전체 이식 (`sim_events.py`)

### 3-1. 두 가지 버전
| | **code** (지금 게임) | **guide** (이벤트 가이드 설계안) |
|---|---|---|
| 배치 | 구간 확률 50/70/70/50% **단계 무관**, 작품당 **최대 2개** | 단계별 확률, 최대 2/3/4개 |
| 선택지 이벤트 | 생일, 퇴근요청, 야매 코드, 장비, 회식, 뒷담, 유튜버, 싸움 (8종) | 기존 9종 + **신규 15종** |
| 선택지 없음 | 경쟁작, 피하는 직원, 감기, 별점 1점, 네트워크, 드릴, 도둑 (7종) | 위 7종 + 신년 운세, 행운 3종, 컨디션 최상, 건물주, 파트 결함 3종, 파트 대박 3종 |
| 투자 제안 | 개발 시작 시 50% 별도 발생 | 일반 이벤트 풀 |
| 조건 이벤트 | 커피/에너지 요청(아이템 획득 시), 불안감 조성, 사내 연애·결별, 커플 동반 퇴사, 팀장 멈춰, 나도 팀장 | 같은 구조, 수치는 가이드 |

### 3-2. 코드와 가이드의 주요 차이
| 이벤트 | 지금 코드 | 가이드 |
|---|---|---|
| 생일 | −5 / +10, 돈 = **그 직원 연봉 3%** (버튼 문구는 총 연봉 3% — **문구와 실제가 다름**) | −10 / +15, R × 5% |
| 퇴근요청 | −5 / +5 + 지연 | −10 + 파트 점수 −1~6% / +15 + 지연 |
| 야매 코드 | 100% 확률, 2주 뒤 개발 팀장 점수 −10% | 50% 확률, 개발 파트 −15~25% |
| 장비 / 뒷담 | 총 연봉 3%, 능력치 +10% (5~15주 / 10~20주) | R × 4.5%, +20% (L주) |
| 회식 | 총 연봉 5% / 10% | R × 6~10% / 10~20.5% |
| 싸움 | 가중치 4, 지금까지 쌓인 팀장 점수 ±10% | 가중치 2.5, μ_part ±9% |
| 투자 | 보상 총 연봉 10%, 목표 = 지난 작품 같은 파트 +5 (거의 항상 성공), 실패 시 1.5배 | 즉시 R × 5%, 실패(42.5%) 시 −R × 10% |
| 피하는 직원 / 별점 1점 | −10 | −25 |
| 감기 / 드릴 | 4~8주 −20% | L주 −20% |
| 커피 요청 | 30% 쏟음(지연), 아니면 +10% 버프 + 만족도 +15 | 70% 버프 ½블록 / 30% 지연 |
| 나도 팀장 | −15, 단계 제한 없음 | −25, 2단계 이상 |
| 팀장 멈춰 | 단계 제한 없음 | 3단계 이상 |
| 커플 동반 퇴사 | **100%** | 50% |

## 4. 단계별 결과

### 4-1. 가정 검증 (`validate`, 가이드 이벤트, P2, 단계별 150판)
| 지표 | 단계 | 가이드 가정 | 시뮬레이터 | 판정 |
|---|---|---|---|---|
| 월간 하락 / 완성 직전 최저 만족도 | 1~4 | 1회 / 80·70·60·60 | 1.00회 / 80·70·60·60 | ✅ |
| 프로젝트당 이벤트 수 | 1~4 | 1.8/1.9/2.4/2.4 | 1.79/1.92/2.42/2.36 | ✅ |
| 파트 1개 비중 | 1~4 | 29% | 29/30/28/26% | ✅ |
| 창의성 비중 | 1~4 | 13% | 13/9/17/22% | ⚠ 4단계 높음 (테크 가정) |
| 팀장 점수 비중 | 1~4 | 52/45/35/32% | 72/53/39/35% | ⚠ 1단계만 (CEO가 직원 없는 파트를 맡음) |
| **만족도 안전/주의/위험** | 1~4 | 90/10/0 … **60/30/10** | 100/0/0 … **97/3/0** | ⚠ **크게 다름** |

### 4-2. 단계별 만족도 가치 (`satvalue`, 1인 +5당 V)
| 단계 | 측정 분포 (안전/주의/위험) | 가이드 공식 × 측정 분포 | 가이드 값 | A/B 직접 측정 (랜덤 직원 / 최저 직원) |
|---|---|---|---|---|
| 1 | 100/0/0 | 0.59 | 1.02 | 0.38 / 0.42 |
| 2 | 99/1/0 | 0.32 | 0.93 | 0.51 / 0.18 |
| 3 | 97/3/0 | 0.19 | 0.79 | 0.01 / 0.18 |
| 4 | 97/3/0 | 0.17 | 0.96 | 0.15 / 0.25 |

**결론**: 이벤트를 모두 넣어도 직원 대부분이 안전 구간에 머뭅니다. 그래서 **만족도의 실제 가치는 가이드의 1/2~1/5 수준**입니다.
- 이유 1: 매달 −5에 비해 완성 시 +40이 커서, 기존 직원은 100 → 60 사이를 오갑니다.
- 이유 2: 위험 구간은 부정 이벤트가 몰리거나 신규 입사자(80으로 시작)일 때만 생깁니다.
- 영향 1: 가이드의 이벤트 선택지 균형("만족도 ↔ 돈·파트 점수")이 **만족도 쪽으로 과대평가**돼 있습니다.
- 영향 2: 만족도 아이템과 최면술사의 시계의 가치가 낮게 나옵니다.

방향은 두 가지입니다.
- **(a) 의도한 만큼 압박을 만든다**: 후반 만족도 압박이 의도라면 월간 하락을 단계별로 키우거나(예: 3·4단계 −7~10), 완성 회복을 단계별로 줄입니다(예: +40 → +30). 그러면 가이드의 분포에 가까워집니다.
- **(b) 지금 분포를 받아들인다**: 가이드의 만족도 환산값(§3-4)을 이 표의 값으로 낮추고, 이벤트 수치를 다시 맞춥니다.

### 4-3. 아웃게임 요소별 효과 (`outgame`, P0에 요소 하나만 추가, 60판)
첫 작품 매출 변화 / 96주 순자산 변화:

| 요소 | 1단계 | 2단계 | 3단계 | 4단계 |
|---|---|---|---|---|
| 카드 레어 (모든 능력치 +50) | +45% | +17% | +10% | +7% |
| 카드 레전더리 | +52% | +22% | +18% | +26% |
| CEO 전 파트 Lv10 | +41% | **0%** | **0%** | **0%** |
| CEO 전 파트 Lv20 | +131% | +17% | +15% | +12% |
| CEO 전 파트 Lv30 | +215% | +22% | +17% | +15% |
| CEO 전 파트 Lv40 | +386% | +60% | +36% | +33% |
| 마케팅의 신 (A) | +20% | +20% | +20% | +20% (+ 마케팅비 0) |
| 만족도 80+ 스탯 +10% (A) / +5% (B) | +11% / +5% | +11% / +5% | +8% / +4% | +8% / +4% |
| 월간 하락 −1 (S) | +0.5% | +1.2% | +1.9% | +5.4% |
| 창의성 블록 +1 (B) | +10% | 0% | 0% | 0% |
| 강화비 할인 / 15성+ 성공률 | 순자산 +2~17V / 4단계 +34V | | | |

- **CEO Lv10은 2단계부터 효과가 0입니다.** CEO 능력치 240이 직원보다 낮아 팀장이 되지 못하기 때문입니다. 1단계에서만 큽니다(직원이 없는 파트를 CEO가 맡음).
- **CEO Lv20/30/40 효과가 문서 예상(2~4% / 5~7% / 9~11%)보다 훨씬 큽니다**(12~17% / 15~22% / 33~60%). 개발 Lv20의 "90/95/99 보너스 ×1.5"와 Lv40의 "파트 점수 +10%"가 큽니다.
- **마케팅의 신이 단일 특성 중 가장 강합니다.** 모든 단계에서 +20%에 비용까지 0입니다(M 1.15 vs 1.05 → 매출 ×1.2).
- 창의성 블록 특성은 1단계 이후 효과가 0입니다(판이 꽉 참).

## 5. 아이템 (`items`, 가이드 이벤트, P2, 50판)

- **공짜로 받으면 대부분 이득**입니다.
  - 업그레이드권: 3·4단계 +10~21V
  - 각성의 물약: +9V
  - 상급 강화권: +16V
- **손해인 아이템**
  - 중급 강화권+: 3단계 −13V. 20·21성 연봉 점프 때문입니다.
  - 초심 회복기: −1~−11V
  - 블록 2종: 0V (판이 꽉 참)
  - 연구노트: 0V (테크트리 미구현)
- **돈을 주고 사면 2~4단계에서 손해**입니다(남은 아이템은 구매가로 계산).

| 단계 | 전부 | 싼 것부터 | 목표V÷가격 | 실측V÷가격 |
|---|---|---|---|---|
| 1 | **+13V** | +15V | +11V | −11V |
| 2 | −8V | −8V | −9V | +0.2V |
| 3 | −8V | −10V | −10V | −5V |
| 4 | −9V | −10V | −8V | −3V |

원인은 **기회비용**입니다. 그 돈을 수익성 있는 강화(§2의 이득 구간)에 쓰는 편이 낫습니다.
- 강화의 손해 구간(§2)을 고쳐서 강화가 더 매력적이 되면 아이템은 더 밀립니다.
- 아이템을 의미 있게 만들려면 **가격률을 낮추거나(현재 효용의 50% → 25~30%), 효과를 강화**해야 합니다.

## 6. 사무실 이전 (요청 반영)
- 시점: 출시 직후 **다음 게임을 시작하기 직전**
- 순서: 이전 → 채용 공고 → 면접 3주 동안 이전 게임 매출이 들어옴 → 빈자리 채용 → 큰 규모로 개발 시작
- 조건: 출시작 평론가 점수가 60/75/85 이상(임시)이고, 다음 단계의 첫 지급을 버틸 돈이 있을 때

`reach` 결과(가이드 이벤트, 40판)는 다음과 같습니다.

| 스펙 | 평균 유저 (2/3/4단계) | 숙련 유저 (2/3/4단계) |
|---|---|---|
| P0 신규 | 8% / 0% / 0% | 92% / 72% / 68% |
| P2 중급 | 42% / 0% / 0% | 100% / 100% / 85% |
| P4 최고 | 100% / 98% / 98% | 100% / 100% / 100% |

평균 유저는 대부분 **연봉**으로, 숙련 유저는 **사무실비**로 파산합니다. 플레이 시간 추정은 50~117분으로 목표(10~15분)보다 깁니다(인지만).

### 7-3. 기획 문서끼리, 또는 문서와 코드가 엇갈리는 것 (확인 필요)
1. **특성 S '강화비 할인'**: 문서 5%(B와 같음) vs CSV 15%. 시뮬레이터는 15%를 씁니다.
2. **특성 S '직원 1~10성 사이 하락X'**: 1~10성은 원래 하락 확률이 0%라서 효과가 없습니다.
3. **레어 카드**: 문서 "모든 능력치 +50" vs 코드 `EmployeeData` "주스탯 +50"
4. **고만족 스탯 특성**: 문서 "80 이상" vs 코드 문구 "81 이상"
5. **창의성 블록 특성**: 문서 "게임마다 +1" vs CSV "시작 시 블록 아이템 1개"
6. **문서에만 있는 특성**: "연봉협상 동결 무패널티", "연구 시간 단축" 2종
7. **기억의 조각**: 코드는 돌 단계 1~7 + 8~10단계 보너스, 문서는 CEO 파트별 레벨 1~40 → 코드가 아직 새 설계로 바뀌지 않았습니다.
8. **생일 이벤트**: 버튼 문구(총 연봉 3%)와 실제 차감(그 직원 연봉 3%)이 다릅니다.
9. 가이드 이벤트 설계안과 지금 코드의 차이는 §3-2 표를 참고하세요.
